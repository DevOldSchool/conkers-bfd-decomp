## Native evidence and source contract

The native index loader uses eight-byte records: a relative offset, a low
28-bit stored size, and four high flag bits. The first relative offset gives
the table extent. Empty entries remain explicit typed records. This batch
uses the existing strict [directory codec](us_asset_directory_reconstruction.md)
and pins the full consumer spans at `1502AC88` (636 bytes,
SHA-1 `24f02469c9605e212ed65a4c75b216d50ef8577e`) and `1502B5C8`
(244 bytes, SHA-1 `9c411ce6bf78e69583215fa8484bfd0f137edc72`).

Alignment uses the same rule as the accepted
[standalone model padding](us_model_alignment.md): advance from the previous
stored payload end by `(-absolute_cursor) % 8`, require the next nonempty
entry to begin exactly there, and require minimum final alignment to the bank
end. Every generated byte must independently equal the checksum-validated ROM.
There is no editable arbitrary fill, length or raw-byte override. Dialogue and
menu text reuse their existing nested directory sources for internal gaps.

`scripts/bank_index_inputs.py` owns the shared derivation. New `bank-index/`
children contain `manifest.json` and `index.json` under the five existing
sprite, visibility, animation-control and route source directories. Existing
parents, PNGs and semantic records are preserved. The other nine groups reuse
existing authored sources and create no new source files.

The production builders compose fresh indexes and alignment into the actual
whole-bank outputs. Make tracks all child inputs, including their deletion.
A changed or missing child fails without replacement; explicit parent recovery
backs up the child before restoration. Source hashes are checked before and
after reconstruction. Native reporting independently compares the generated
ranges from actual linked objects to the ROM and checks the whole linked object
against the fresh composed candidate. No backing payload earns new credit.
