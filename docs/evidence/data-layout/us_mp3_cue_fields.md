# US MP3 animation-command fields

Accepted reconstruction: **68,992 bytes**, comprising seven consumed or structural bytes in each of 9,856 nine-byte
records across 220 MP3 streams. The other two bytes remain opaque and excluded.

## Native transport and consumer

`mp3main_continue_file` (`151F86B0`, 436 bytes) reads a NUL-terminated record
after a successfully decoded copyright-marked MPEG frame. It forwards the
record, including its terminator, through the callback at `800E0E00`.

The initialization path at `80012588` creates the ring buffer at `800427A0`
and calls the GAME setter `851F3C1C` with execution alias `10012560`. That
callback writes the record through `15043BB8`; `800126E8` retrieves it through
`15043CA4`. The ring stores a rounded length and copies the record unchanged.
These main/GAME execution aliases explain why an earlier lookup for only
`151F3C1C` did not find the registration path.

`15080228` drains that queue into a 256-byte local buffer. It accepts a first
byte of `L`, then decodes bytes 4 through 7 as four seven-bit, big-endian groups.
It divides that integer by 367, substitutes 20 for a zero quotient, and passes
the result with `buffer[3] - 1` to `15080430` for the selected actor. The latter
handles stop/special animation modes and clamps the transition parameter before
calling `1507E500`. No speaker, subtitle or character identity is inferred.

Full spans of the registration, callback setter, transport helpers, record
decoder, consumer and animation dispatcher are checked against the US ROM.
The transport and parser establish field boundaries independently of observed
cue timing. The timing probe agrees with next-cue sample separation to within
one MPEG frame for 9,624 of 9,636 intervals, but this correlation is not used
to grant matching credit or to assert a physical unit for the integer.

## Partial record contract

| Offset | Interpretation | Generated bytes |
| --- | --- | --- |
| 0 | Native command discriminator | `L` |
| 1–2 | Unconsumed delimiter/subtype bytes | Excluded |
| 3 | Animation action plus one | One nonzero byte |
| 4–7 | Duration numerator | Four seven-bit groups, each with its high bit set |
| 8 | Transport terminator | NUL |

The high-bit-set encoding preserves every seven-bit group while preventing a
zero group from terminating the transport string. All reviewed records use
this form; other encodings are rejected. The editable source stores an integer
action and duration numerator, never raw byte arrays or an opaque override.
Field widths and frame placements are checked. Bytes 1–2, incomplete MPEG
reservoir bytes and unrelated stream tails remain backed by original inputs
without credit.

## Build and validation

The asset build initializes a separate `build/assets/mp3-cues/us/<entry>/`
child with `manifest.json` and editable `commands.json`. It composes freshly
encoded cue fields with the existing spectral and metadata ranges before
writing the actual stream linker input. Source hashes cover all three families
and the original backing, and the report checks the same disjoint physical
ranges against the real linked object and independent ROM bytes.

Make tracks source edits and deletions. Existing damaged or edited sources
fail without overwrite. Explicit `./conker mp3-assets recover-cues --entry <id>`
backs up only that entry's cue sources before restoring the reviewed record.
Field widths, extra keys, record counts and frame placements are checked;
input changes during encoding are rejected.
