# US MPEG final-frame fields

The original spectral reconstruction selected only complete physical MPEG frames.
All granules were already represented as typed coefficients, including granules
in the final frames. This extension reconstructs the remaining 2,078 frame
headers and side-information blocks, plus complete reservoir bytes before the
last encoded bit. The added coverage is **36,479 bytes** across 453 streams:
27,014 bytes of headers/side information and 9,465 coefficient bytes.

The existing typed sources are reused unchanged. This is a bounded extension of
`scripts/mp3_spectral_codec.py`, not a new decoder or a change to audio values.
The prior four complete native MP3 consumer spans and independently authenticated
Huffman/lookup tables remain the provenance gate.

## Exact boundary

For each physical frame, native MPEG framing gives its size and the 13-byte
header/side-information prefix. `main_data_begin` and `part2_3_length` locate
each granule in the shared reservoir. The encoder writes freshly generated
scalefactor, Huffman, linbit and sign bits into that reservoir exactly as before.
Its final endpoint is rounded **down** to a complete byte. A physical frame
contributes its typed 13-byte prefix plus the complete reservoir bytes before
that endpoint. Later frames still contribute their typed prefixes.

A byte with even one unknown bit is wholly excluded. Conker's nine-byte cue
records, unresolved reservoir suffix and arbitrary trailing storage remain
uncredited. Physical advancement always uses the full stored frame size and
cue length, even when only the header is credited. Adjacent generated slices
merge; ungenerated bytes retain explicit gaps.

The public codec's default full-frame mode is preserved. The actual ROM builder
and native report explicitly request bounded partial output. The saved manifests
continue to authenticate their original full-frame contract; the builder also
checks that contract against original framing before deriving the new ranges.
A source change affecting only a formerly omitted final header now fails exact
reconstruction instead of silently drawing that header from raw backing.

## Independent checks

The audit uses a separate direct bit-field reader for original frame sizes,
back-pointers and granule lengths. It independently derives every new physical
range and compares all generated bytes with the checksum-validated ROM.
Each of the 2,078 formerly omitted headers has an in-memory global-gain mutation
that changes fresh output. Every prior editable-source hash remains unchanged.
The adjacent JSON records each stream's added intervals and incomplete-bit count.

Focused tests cover a final half-byte containing deliberately nonzero unknown
bits, header-only frames after the last granule, cues between those frames,
last-frame coefficient/header edits, source races, preserved invalid inputs,
stale manifest counts and the actual linked-object bounded report.

The existing 453 native spectral units grow; no duplicate units or overlapping
ranges are introduced. Their previous physical slices remain covered. All other
asset units and the global Data denominator must remain unchanged at acceptance.

## Accepted checkpoint

The full US asset build reproduced the original 67,108,864-byte ROM in 67 seconds
(SHA-1 `4cbadd3c4e0729dec46af64ad018050eada4f47a`). All 2,591 Docker tests passed
in 133.555 seconds (8 skips). Native objdiff, progress and whitespace gates passed.
Matched Data is 62,200,104 / 65,120,512 bytes (95.51537%); code measures and unit
counts are unchanged. The independent report audit preserved all prior ranges,
26,052 source hashes and all 10,228 other asset proofs. The adjacent JSON records
the exact source fingerprint and report hash for base commit
`094102644c4c2f5aefaa0fc4b609416918f66f58` with these uncommitted changes.
