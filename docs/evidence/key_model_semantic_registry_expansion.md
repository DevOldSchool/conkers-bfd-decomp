# Reviewed text-entry key-model registry expansion

Historical checkpoint: the reviewed/named totals below count source-bound
descriptive labels, not confirmed semantic identities or distinct characters.
Gallery labels and source hashes do not establish human confirmation. The
[current confidence review](model_name_confidence_review.md) supersedes the
old reviewed/unknown naming status; source pins and validation history remain
evidence for their stated scope.

This adds thirty exact bank-09, segment-zero descriptive labels to the
[reviewed registry](../../config/model-semantic-names.json), taking 202 reviewed
models to 232. The complete 1,487-model corpus retains 1,255 unknown models.
All 202 prior records, their consumer associations and Haybot's model-specific
branch are preserved. No canonical record, source model, geometry, material,
scene association, linked symbol, C implementation or match status changes.

The source-role review [Text-entry key model roles](text_entry_model_role_names.md)
explains the initializer, selection/submission logic, caller tables and dynamic
text-bank route. This note binds those complete consumers to exact reviewed
model payloads. The labels are authored descriptions of stored geometry and
visible glyphs, not recovered original names or evidence of runtime activation.

## ROM and independent numeric joins

Normalized US ROM size is 67,108,864 bytes, SHA-1
`4cbadd3c4e0729dec46af64ad018050eada4f47a`, SHA-256
`32e6a8b970ec12ac5f782344945aa0c98a193832eefb687529d03bab6948714b`.
The numeric bank/entry/segment from each direct ROM extraction was joined to
exactly one preview-manifest row, one validation source and one canonical render
case. The original compressed extents, decoded size and both hashes were
recomputed. Header, vertex, ordered-face and display-list reconstruction is
byte-identical; source UVs/colors and 31 distinct linked flat texture payloads
reproduce the preview data and texture PNGs. Current dependency fingerprints and
render hashes bind the five inspected contact sheets to those exact exports.
Filenames and captions are not the numeric or visual identity authority.

All thirty actual rendered models were inspected. Entries 453–476 show A–X;
477 shows DEL, 478 a dot, 479 Y, 480 Z, 481 a return arrow, and 482 a long blank
key. Letter resources are not a contiguous A–Z interval. Canonical JSON already
says “Letter block”; none of its labels, notes, aliases, IDs, categories or paths
is corrected by this expansion. Existing canonical corrections stay intact.

Every model has a 40-byte direct header and ten full-source faces. Entries
453–481 have twelve vertices and entry 482 has fourteen: 300 faces and 362
vertices in total. Primary lists begin at offset 232 except entry 482, whose
list begins at 264. Lists are 208 bytes through entry 480, and 224 bytes for
481–482. These are stored direct models with no stored joint/animation inventory.
The normal keys span 40 units horizontally, the return key 80, and the blank
key 240; the blank shape alone would not establish the space action.

Activation tests input bit `0x10`. The normal initialized text path retains at
most nineteen characters plus its terminator despite allocating 32-byte buffers.
UI state 3, resource slot, bank entry, character byte and flat texture index are
separate namespaces; UI state 3 is not a scene ID.

## Stored appearance and behavioral limits

The source material images identify the glyphs and key shapes. The initializer
changes the first two referenced vertex colors from yellow to opaque black,
replaces `FC121824/FF33FFFF` with `FC127E05/FFFFF3F8`, and replaces
`EF08AC3F/00552230` with `EF18AC3F/0F0A4000`. Selection further adds live alpha,
environment color and transforms. The source previews do not reproduce these
initialized/dynamic materials or establish native lighting, blending, raster
appearance or visibility. No asset or renderer correction is made.

Submission compares nineteen padded positions against 32 candidate columns,
updates a bit field for a surviving candidate, or follows word/repetition
feedback paths. This does not establish player-name storage or persistent-save
behavior. Static call/data-pointer scans do not exclude computed routes, overlays
or runtime patching; no exclusive controller, character/voice identity, actual
activation, parent placement or full native appearance is claimed.

summary, source/scene/runtime evidence field and input manifest identity is
unchanged. Naming neither creates scene associations nor upgrades appearance or
